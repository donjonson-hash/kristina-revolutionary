# Состояние и ритм Кристины

Первый шаг к непрерывности характера: состояние переживает перезапуск,
реагирует на события и влияет на темп и тон общения. Это инженерная модель
поведения; коэффициенты — стартовые настройки персонажа.

## Единый источник состояния

Telegram Persona, BrainBridge и инициативные сообщения используют один
`get_emotional_core()`. MoodEngine больше не ведёт отдельную энергию или
счётчик усталости. Семь существующих величин сохраняются: энергия, радость,
любопытство, тревожность, одиночество, креативность и раздражение.
Пять базовых черт характера остаются константами кода.

Состояние общее для Кристины: разговоры с разными людьми могут влиять на её
энергию. Тексты, имена и идентификаторы собеседников в эту базу не попадают.
Изоляция истории разговоров из PR #18 сохраняется. `/clear` очищает разговор,
но не сбрасывает характер и общее эмоциональное состояние.

## Время и события

- Метки времени хранятся в UTC; день и ночь определяются в Europe/Stockholm.
  Ночь: 23:00–08:00 с учётом переходов летнего времени.
- Между событиями состояние плавно приближается к часовым ориентирам:
  `target + (value - target) * exp(-elapsed_hours / 4)`.
  Интервалы разбиваются по часовым границам. Результат не зависит от количества
  вызовов heartbeat. Простой приложения обрабатывается тем же способом.
- Ориентир энергии: 0.25 ночью, 0.85 в 08–11, 0.75 в 11–14,
  0.60 в 14–17 и 0.55 в 17–23. Это доступность для общения:
  низкая ночная величина означает сонливость. Днём отдых восстанавливает
  истощённую энергию. Любопытство тяготеет к 0.8 днём, 0.65 вечером,
  0.35 ночью; одиночество — к 0.5 вечером и 0.4 в остальное время.
- Одно сообщение в Persona даёт небольшой эффект: энергия −0.025,
  любопытство +0.015, одиночество −0.04. Быстрый длинный разговор накапливает
  усталость; пауза даёт время на восстановление.
- Существующий явный флаг `negative_tone` добавляет 0.2 к раздражению.
  Автоматическое определение эмоционального смысла текста в этот PR не входит.
- Случайные изменения каждой эмоции при каждом тике убраны.
  Непредсказуемость темпа сохраняется внутри диапазона выбранной паузы.

## Ритм ответа

| Состояние | Условие | Пауза до генерации |
| --- | --- | --- |
| Вовлечённость | Энергия > 0.6, любопытство > 0.7, день | 15–30 с |
| Спокойствие | Остальные дневные состояния | 30–60 с |
| Усталость | Энергия < 0.4, день | 45–90 с |
| Сонливость | 23:00–08:00 в Стокгольме | 60–120 с |

Persona фиксирует один снимок после события входящего сообщения и выбирает
по нему тон и одну паузу. Снимок сохраняется в `AgentResponse.context_used`,
а причина задержки записывается в журнал без текста сообщения.
Фоновое обновление во время ожидания не подменяет этот снимок.
Время вызова модели и других инструментов добавляется к паузе.

Ночной ответ формируется с историей разговора и ночным модификатором:
случайная готовая реплика больше не отбрасывает сообщение до генерации.
Кристина может предложить вернуться к разговору завтра. Встречный вопрос
при любопытстве становится возможностью, а не обязательным шаблоном.

## Хранение и эксплуатация

`KRISTINA_STATE_DB` задаёт путь к SQLite, по умолчанию `kristina_state.db`
в рабочем каталоге приложения. Дополнительные зависимости не нужны.
Каталог должен существовать и быть доступен на запись. Для разных рабочих
каталогов следует задать одинаковый абсолютный путь к базе общего персонажа.

Таблица `emotional_state` содержит один версионированный снимок и последние
20 событий (только тип и время). При записи используется транзакция
`BEGIN IMMEDIATE` с повторным чтением актуального состояния: разные процессы
не перезаписывают чужие события устаревшим снимком. Ошибка записи откатывает
транзакцию и локальное состояние; повреждённая база не заменяется молча новой.

База исключена из Git существующим правилом `*.db`. Текущий деплой обновляет
код без удаления этой базы. При замене VPS или рабочего каталога перенесите
файл отдельно. Стандартный путь добавлен в `backup.sh`; этот существующий
скрипт копирует файлы, поэтому запускайте его при остановленных писателях.
Для резервирования работающего приложения используйте SQLite backup API.
При нестандартном пути настройте резервирование этого файла отдельно.

Прямой `EmotionalCore()` создаёт изолированную модель в памяти для тестов
и экспериментов. Рабочая интеграция использует `get_emotional_core()`.
Отдельный экспериментальный `KristinaLife` в этом PR не подключается к боту.

## Проверка и границы этапа

Тесты проверяют перезапуск, время простоя, переходы DST, обратный скачок часов,
независимость от частоты тиков, накопление усталости и восстановление,
конкурирующие записи, повреждённую базу и откат при ошибке записи.
Интеграционные проверки проходят настоящий путь Persona с подменёнными
LLM/ожиданием и проверяют общий источник состояния для инициативных сообщений.

Планировщик сообщений здесь не меняется: обработчик всё ещё ожидает ответ,
незавершённая пауза не сохраняется при остановке процесса. Объединение новых
сообщений во время ожидания, отмена устаревших ответов, сохраняемые намерения
и собственные интересы — отдельный следующий этап. Оценка смысла события,
фильтр ответа и параметры AI-адаптера также остаются отдельной работой.
