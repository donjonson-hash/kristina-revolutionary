# Scout 0.4.1: локальный прототип

Отдельный персональный тренд-агент: Chrome side panel + локальный Express backend.
Этот каталог не подключён к Telegram-ядру Кристины и не меняет проект сверки документов.
Публичный многопользовательский сервер, платежи и аккаунты не входят в эту версию.

## Откуда код

Исходный снимок: пользовательский архив `scout-v0.4.0-llm-ready.zip` от 28 сентября 2026.
SHA-256 архива: `55e4a789d9d3561c14ad079900f7f608cec2918f0de000e8e4ca3e59eae4c8b9`.
Первый коммит импорта сохраняет девять файлов v0.4.0, кроме очистки placeholder
ключа в `.env.example`; последующий коммит содержит стабилизацию 0.4.1.

## Локальный запуск

Требуются Node.js 24, npm, curl и Chrome 120+. Сервер слушает только
`127.0.0.1:3456`; расширение обращается к этому адресу, а не к удалённому серверу.

1. Откройте `chrome://extensions`, включите Developer mode и загрузите
   `scout/extension/` через Load unpacked.
2. Скопируйте ID Scout с этой страницы.
3. Установите зависимости и создайте локальную конфигурацию:

```bash
cd scout/server
npm ci --ignore-scripts
cp .env.example .env
```

В `.env` установите `SCOUT_EXTENSION_ID` в ID расширения. Для keyword-only режима
оставьте `OPENROUTER_API_KEY` пустым; для LLM укажите собственный ключ OpenRouter
и доступный вашему аккаунту `OPENROUTER_MODEL`. Проверка модели и ключа вживую
не выполняется автоматически; `/health` сообщает только наличие конфигурации.

```bash
npm start
# В другом терминале:
curl http://127.0.0.1:3456/health
```

Откройте side panel, задайте нишу, выберите 1–7 тем и нажмите «Проверить сейчас».
Если меняете `PORT`, необходимо согласованно изменить `API_BASE` в двух файлах
расширения; для обычного запуска оставьте порт 3456.

Никогда не коммитьте `.env`. Legacy-переменные `OPENAI_API_KEY`/`OPENAI_MODEL`
поддерживаются только для совместимости с локальной v0.4.0; запросы идут в OpenRouter.
Имя модели намеренно не выбрано за пользователя.

## Что стабилизировано

- Проверяются типы, длины и количество полей; malformed topics возвращают 400,
  а rejected Promise не завершает Express 4.
- Размер JSON-запроса ограничен 16 KiB; сервер допускает один `/digest` одновременно
  и до пяти принятых запросов за минутное окно.
- Источники имеют общий deadline 7 секунд и лимит ответа 1 MiB; недоступность
  всех источников возвращает 503, отсутствие сигналов — явный `no_data` без LLM.
- Модель выбирает только существующие IDs. URL/title/source/score подставляются
  из исходных сигналов; неизвестные IDs, повторы и неверная схема дают keyword fallback.
  `meta.llmFailed` отличает отказ LLM от режима без ключа.
- Curl сохранён как транспорт, но запускается асинхронно без shell. Prompt идёт
  через stdin; ключ хранится только в временном config-файле с mode 0600 внутри
  каталога 0700, который удаляется в `finally`. Содержимое ответов и ключи не логируются.
- Worker сериализует генерацию до первого `await`, хранит lease на 35 секунд
  и восстанавливает просроченные заявки, включая legacy `claimedAt`.
- Ошибка не заменяет последний дайджест и не меняет время последнего успеха;
  retry идёт через 5/10/20/40/60 минут с учётом quiet hours.
- Период выбирается из профиля: 1 или 3 дня. Alarm одноразовый, восстанавливается
  при старте, изменении профиля и после попытки; quiet hours переносят его на конец
  тихого периода по локальному времени браузера.
- Ручной запуск обходит расписание и quiet hours, но не активную генерацию.
- Уведомление имеет локальную иконку и отдельную обработку ошибки; отказ уведомления
  не отменяет сохранённый дайджест и не повторяет LLM-запрос.
- Панель обновляется по storage events, показывает сбои и сохраняет настройки
  при повторном открытии онбординга. Дайджест хранит свою нишу, поэтому старый
  результат не выдаётся за результат нового профиля.

## Граница безопасности

Это инструмент для доверенного локального пользователя, а не SaaS-auth:

- Сервер привязан к loopback и проверяет Host против DNS rebinding.
- Browser Origin допускается только для указанного `SCOUT_EXTENSION_ID`.
- POST требует JSON и `X-Scout-Client: 1`, чтобы обычная страница не могла
  отправить запрос простой HTML-формой.
- Локальный процесс может самостоятельно выставить заголовки; этот прототип
  не изолирует пользователей одной машины друг от друга.
- Не выставляйте порт через tunnel/reverse proxy в интернет без отдельной
  аутентификации, бюджетов и эксплуатационной проверки.

Пример локального диагностического запроса:

```bash
curl http://127.0.0.1:3456/probe \
  -H 'Content-Type: application/json' -H 'X-Scout-Client: 1' \
  -d '{"niche":"AI tools for developers"}'
```

## Тесты и CI

```bash
cd scout/server
npm ci --ignore-scripts
npm test
```

Тесты используют реальные loopback HTTP-запросы к Express 4, mock источники/LLM,
VM для worker и JSDOM для панели. Провайдерские ключи и платные запросы не нужны.
Отдельный workflow `Scout CI` выполняет syntax checks и регрессионный набор;
существующие проверки Кристины и сверки документов не заменяются.

Это не полноценный Chrome E2E: перед выпуском вручную проверьте загрузку расширения,
`/probe`, ручной дайджест, реальные уведомления, смену частоты и рестарт браузера.
После локальных тестов отдельно согласуйте live проверку своего OpenRouter key/model.

## Что пока не обещаем

- Score поста — снимок популярности, не измеренная скорость роста тренда.
- Keyword fallback остаётся простой эвристикой, особенно для русских тем и английских заголовков.
- Привязка ссылки к источнику не доказывает фактическую истинность поста или модельного explanation.
- Нет облачного push при выключенном браузере/ноутбуке, OCR, CRM, платежей или командной работы.
- Никаких автоматических merge/deploy: стабилизация проводится отдельным PR.
