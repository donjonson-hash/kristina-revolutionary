# 🔬 Анализ проектов из отчётов TrendScout

Здесь живут углублённые проверки идей, которые бот Kristina (агент TrendScout)
отобрал в еженедельных отчётах (Σ ≥ 20 по методологии `trend_scout_prompt.py`).

Отчёт TrendScout — это гипотеза, построенная на сигналах за неделю.
Перед стартом работ каждая идея проходит ручную валидацию:

1. **Проверка фактов** — существует ли тренд, верны ли цифры из отчёта.
2. **Карта конкурентов** — кто уже решает эту боль (отчёт видит спрос,
   но плохо видит предложение).
3. **Пересчёт скоринга** — те же 6 критериев, но по проверенным данным.
4. **Вердикт** — делать / пивот / отклонить, с обоснованием.

Формат имени файла: `YYYY-MM-DD_<slug>.md` (дата = дата анализа).

Остальные пивоты (managed-DNS, compliance-форж, agent-governance, LLM SLA-watchdog)
жизнеспособны только как узкий сервисный B2B с ограниченным upside.

### Урок для методологии (`trend_scout_prompt.py`)

Во всех 8 случаях просел один критерий — **«Конкуренция»**: бот выводил балл из
отсутствия конкурентов в собранных сигналах, а не из явного поиска существующих
решений. Рекомендация: в Шаге 4 требовать явный ответ «кто уже решает эту боль —
назови продукты и их масштаб» до выставления балла. В быстрых нишах (AI-инфра)
окно между «боль есть» и «боль закрыта бесплатно» — недели.
