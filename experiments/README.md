# Связи между эмоциональными состояниями: пилот Drydock → Kristina

Это отдельный **offline shadow-эксперимент**: детерминированные обработчики передают
числовые импульсы между существующими осями `EmotionalCore`. Рабочий pipeline,
память, ответы и службы Кристины не подключены к этому модулю.

## Что перенесено из Drydock

Самостоятельно реализованы архитектурные принципы, проверенные в
[shipit на 405cc1f6](https://github.com/aiagent2046-coder/shipit/tree/405cc1f6dc47cecc2c2671ced9aad10ede644500):

| Механизм Drydock | Реализация пилота |
| --- | --- |
| Ограниченная очередь `app/scan/agent_chain.py` | Очередь активных связей; максимум 16 обработчиков на событие, по одной попытке |
| Проверка предложений до принятия | Передача по зарегистрированному ребру, отдельный verifier, затем атомарное обновление shadow-состояния |
| Копии при передаче данных | Изменение возвращённого результата или входных словарей не меняет принятое состояние |
| Привязка результата к исходным данным | Хеши события, правил и предыдущего принятого результата; происхождение `synthetic_fixture` |
| Контролируемая мутация и обратное восстановление | Отключение одного ребра, проверка именно утраты торможения, восстановление из изменённого графа |

Исходный код Drydock распространяется под AGPL-3.0-or-later. Код его сканера не
копируется и не импортируется; здесь новая небольшая реализация этих принципов.
Это не перенос SQL/AST-сканера и не запуск нескольких LLM-агентов.

## Модель

Сохраняются семь осей ядра: `energy`, `happiness`, `curiosity`, `anxiety`,
`loneliness`, `creativity`, `irritation`, каждая в диапазоне `[0.1, 1.0]`.
В первом опыте активны четыре связи:

| Источник | Получатель | Вес |
| --- | --- | ---: |
| anxiety | curiosity | −0.40 |
| curiosity | creativity | +0.50 |
| irritation | happiness | −0.30 |
| happiness | anxiety | −0.25 |

Веса — ручные параметры гипотезы, а не результат обучения или установленная модель
психики. Отрицательный вес тормозит получатель при положительном импульсе источника;
при отрицательном импульсе знак воздействия меняется. Слова «центры» и «связи» здесь
обозначают числовые состояния и обработчики событий, не биологические нейроны.

Для каждого события:

```text
direct_delta = state_after_event - state_before_event
offset = clip(exp(-elapsed_seconds / 7200) * previous_offset + W * direct_delta,
              -0.12, +0.12)
shadow_state = clip(baseline_state + offset, 0.1, 1.0)
```

Оба снимка события берутся в один момент, **после** обычного circadian evolution.
Суточное изменение состояния не считается новым импульсом. Базовое ядро продолжает
своё существующее затухание с τ=4 часа; добавка связей затухает отдельно с τ=2 часа.
В таблице результатов указаны безразмерные изменения состояния, не проценты эмоций.

Каждое активное ребро получает только прямой импульс. Эффект одного ребра не
возвращается в очередь и не становится источником для другого ребра в том же или
следующем событии. Поэтому даже циклический каталог не вызывает самовозбуждения.
Shadow-добавка не записывается в baseline; это намеренное ограничение первого опыта.

## Запуск и результаты

Из корня репозитория, Python 3.11+; внешние зависимости не нужны:

```bash
python -B -S -m experiments.replay_emotional_links --summary
python -B -S -m experiments.replay_emotional_links
```

Первая команда печатает компактный результат, вторая — полную трассу каждого
события: входные снимки, дельты, вклад каждого ребра, затухание, оба ограничения,
состояние и хеши. Команды не сохраняют файлы. Код возврата 0 означает прохождение
всех объявленных проверок; иначе 1. [result.json](result.json) — сохранённый компактный
результат этого запуска. Хеши служат проверке воспроизводимости внутри одной среды;
между платформами/версиями libm возможны последние разряды float.

Четыре одинаковые последовательности синтетических числовых событий проходят через
отдельные `EmotionalCore(db_path=None, clock=...)`:

1. **control** — существующее ядро, связи отсутствуют;
2. **linked** — все четыре связи;
3. **mutant** — только вес `anxiety → curiosity` заменён на 0;
4. **restored** — в mutant-копии этому ребру возвращён исходный вес.

| Воздействие | Измеренный новый вклад |
| --- | ---: |
| curiosity +0.08 | creativity +0.0400 |
| anxiety +0.06 | curiosity −0.0240 |
| irritation +0.06 | happiness −0.0180 |
| happiness +0.03 | anxiety −0.0075 |

У mutant исчезает только выбранное торможение; остальные связи сохраняют свои
результаты. Восстановленный граф, все состояния и полные трассы совпадают с linked.
Через четыре часа без событий остаётся `exp(-2) ≈ 13.53%` последней добавки.
Все 10 причинных/числовых проверок пройдены (`supported_on_cases`). Это подтверждение
механизма на данных fixtures, не доказательство улучшения диалога или субъективных чувств.

## Границы и проверки

- Только синтетические источники: сообщения пользователя и самоописания модели сюда
  не принимаются. Смысл текста этот слой не извлекает; в рабочей Кристине оценка
  сообщения `assess_event` по-прежнему использует LLM.
- `source_ref` и хеши связывают числа с fixture, не доказывают подлинность внешнего
  события. Полные receipts не являются исполняемыми инструкциями.
- Максимум 128 принятых событий на replay. Старые ID не вытесняются: точный повтор
  возвращает исходный результат, повтор с другими данными отвергается. Эта гарантия
  действует только внутри одного объекта в памяти, не между перезапусками.
- Неверные входы, обратное время и сбой обработчика отклоняют событие без частичного
  обновления. Превышение бюджета действий возвращает `blocked`, сохраняя прежнее
  состояние. Отклонённый ID не считается принятым.
- При ограничении добавки и итогового состояния trace показывает потерянную величину.
  Чтение `sample` не меняет состояние и не порождает новых импульсов.
- Эксперимент не создаёт singleton ядра, BrainBridge, MoodEngine или event bus.
  Тест свежего процесса блокирует сеть, subprocess, SQLite и запись файлов и
  проверяет, что модули LLM/рабочего pipeline не загружены.

```bash
python -m pytest tests/test_emotional_links.py -q
```

Следующий этап — observer уже проверенной оценки в действующем pipeline, с однозначным
ID и атомарным снимком «до/после». Он не должен повторно вызывать `assess_event`,
`react` или `evolve` и не должен публиковать собственные ответы как новые факты.
Сначала сравнивать shadow с реальным ядром; влияние на поведение, долговременные
веса и обучение потребуют отдельного эксперимента и критерия полезности.
