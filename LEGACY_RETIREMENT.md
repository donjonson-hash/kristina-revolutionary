# Границы очистки старых интерфейсов

Решение от 30 сентября 2026: основной приоритет Кристины — мозг, память и личность
в Telegram-боте `@krististigai_bot`. Старые мобильное приложение, mini-app и
веб-панель больше не нужны; новую систему JWT-аккаунтов для них не развиваем.

## Удалено из исходного кода

- `mobile_api.py`, `mobile_app/` и `mini_app/`, включая старый APK.
- `web_server.py`, `templates/index.html`, `static/css/dashboard.css`,
  `static/js/dashboard.js` и `deploy/kristina-web.service`.
- Старые установщики `server-setup.sh`, `install-service.sh`,
  `kristina-manager.sh` и диагностика `test_server.sh`.
- Тесты удалённых интерфейсов: `tests/test_api.py`, `test_mini_app.py`,
  `test_mini_app_integration.py` и неиспользуемая Mobile API fixture.
- Специфичные зависимости старой авторизации: `python-jose`, `passlib`, `slowapi`.
- Отдельные инструкции старых интерфейсов: `SERVER-README.md`,
  `MINI_APP_TEST_REPORT.md` и инструкции внутри удалённых каталогов.

Исторические отчёты и планы не являются актуальным описанием runtime.
В частности, старые рекомендации по Mobile API/JWT не означают, что этот API
остаётся поддерживаемой частью проекта.

## Сохранено без изменения поведения

- Telegram entry point `bot.py`, router, persona, эмоциональное и диалоговое
  ядро, память, когнитивная оценка, намерения и проактивность.
- TrendScout внутри Telegram и его сборщики. Локальная новая версия Scout
  будет проверяться отдельно; её нельзя заменять старой опубликованной веткой.
- Весь отдельный проект сверки документов: `extension/`, `static/reconciliation/`,
  `avatar_platform/`, `reconciliation_web.py`, `reconcile_lists.py`,
  примеры, документация, build scripts и все его Python/JS/UI-тесты.
- Общие зависимости сверки документов, включая FastAPI и uvicorn.
- `document_handler.py`, `document_processor.py`, `pricing_config.py`:
  Telegram-бот пока использует эти модули. Их возможное упрощение не входит
  в удаление старых интерфейсов.
- Базы данных, `.env`, секреты, git history, другие ветки и действующий
  systemd unit Telegram-бота.

## Регрессионные проверки

- Изолированный импорт и регистрация Telegram-агентов без JWT-секрета,
  запрещённых legacy imports и сетевых обращений.
- Отсутствие удалённых entry points и установщиков.
- Существующие проверки диалогов, изоляции памяти, restart/replay,
  эмоций, проактивности и TrendScout.
- Существующие проверки и сборка отдельного проекта сверки документов.

Число тестов уменьшится из-за удаления тестов упразднённого Mobile API.
Это не отключение проверок Telegram или документов: они остаются в CI.

## Отдельный серверный этап, не выполненный этим изменением

Удаление файлов из Git не останавливает уже запущенный Python-процесс, не
удаляет ранее скопированный systemd unit и не закрывает сетевой порт.
Без проверки нельзя заявлять, что старые endpoints уже недоступны в production.

Перед отдельным согласованным отключением необходимо:

1. Проверить действующие services, их `ExecStart`, рабочие каталоги и порты.
2. Убедиться, что `kristina-api`/старый `kristina-web` не обслуживают Scout
   или отдельный проект документов; имена сервиса недостаточно.
3. Проверить резервные копии памяти и эмоционального состояния Telegram-бота.
4. Согласовать остановку только подтверждённых legacy-сервисов.
5. Проверить `@krististigai_bot` после изменения, не публикуя секреты.

PR не выполняет remote shutdown, migration, merge или production deploy.
Возврат исходников возможен обычным revert коммита, без переписывания истории.
