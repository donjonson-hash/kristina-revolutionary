# Восстановление Telegram-контекста после рестарта

Реестр runtime-состояния хранится в существующей `kristina_memory.db`. Новая БД,
Redis и изменение Telegram-токена не требуются; память диалога и эмоциональное
ядро продолжают работать прежним путём.

## Что сохраняется

- TTS-настройка по пользователю.
- Выбранный режим по Telegram-пользователю и чату, включая групповые чаты.
- Только ранее зарегистрированные активные личные чаты.
- Время последней личной активности и следующая возможность проактивного решения.

Запись выполняется до обновления RAM-кэша и подтверждения изменения настройки.
Миграция добавляет три таблицы `telegram_*`, не меняя сообщения, receipts,
диалоговые паузы и эмоциональную базу.

## Запуск без немедленной рассылки

`main()` вызывает `restore_telegram_runtime()` до регистрации jobs и запуска polling.
Настройки восстанавливаются одной транзакцией; при ошибке не публикуется частичный
RAM-снимок, а запуск не продолжается с выдуманными defaults.

Для каждого известного личного чата следующая возможность определяется как максимум
сохранённого времени и `now + новый jitter`. По умолчанию jitter составляет
17–53 минуты; используются прежние `KRISTINA_AUTONOMY_MIN_MINUTES` и
`KRISTINA_AUTONOMY_MAX_MINUTES`. Просроченные возможности не «догоняются» рассылкой.

Возможность принять решение не равна отправке. Существующий `DialogueStore` всё
так же проверяет паузу, открытый вопрос, лимит инициативы, cooldown и незавершённую
доставку `sending`; restore не снимает и не переписывает эти ограничения.

`/start` больше не сбрасывает уже выбранный режим и TTS. `/clear` по-прежнему
очищает историю, но не является командой отключения проактивности или сброса
настроек; удалённый текст не восстанавливается из runtime-реестра.

## Первый переход со старой версии

Старая версия не сохраняла активные чаты, поэтому восстановить её потерянный
RAM-набор достоверно невозможно. Автоматического зачисления всех исторических
собеседников нет: после первого внедрения нужна обычная личная реплика или `/start`,
чтобы чат появился в новом реестре. После этого следующие рестарты его сохраняют.

Настройки режима и TTS фиксируются при их изменении; отсутствующие записи
получают прежние defaults. Выбор режима или TTS в группе не разрешает боту
инициировать личное сообщение этому пользователю.

## Границы

- Стабильные файлы БД и рабочий каталог остаются обязательными.
- Резервное копирование `kristina_memory.db` включает новый реестр.
- Последние начала proactive-реплик (`recent_proactive`) остаются кратким RAM-кэшем;
  сохранённая история и диалоговые блокировки при рестарте не теряются.
- Этот PR не решает отдельное окно аварии между commit эмоциональной реакции
  и commit входящего диалога. Оно требует собственной идемпотентности эмоций.
- Scout, сверка документов, личность Кристины и транспорт Telegram не изменяются.
- Merge и production deploy выполняются только после отдельного согласования.

## Проверки

```bash
python -m pytest tests/test_telegram_runtime.py -q
python -m pytest tests/ -q
```

Регрессии проверяют настоящий SQLite, два независимых Python-процесса,
восстановление истории и эмоций вместе с настройками, отсутствие отправки
сразу после запуска, сохранение блокировок, возобновление после истечения
паузы, изоляцию групп и rollback при ошибке записи. Внешние модельные вызовы
и доставка Telegram подменены: тесты не отправляют сообщения пользователям.
