# Кристина: помощник по сверке данных

Первый исполняемый профессиональный сценарий: два CSV → явные правила →
проверка неоднозначностей → точная сверка → JSON и самостоятельный HTML-отчёт.
Доступны CLI, локальный браузерный интерфейс и автономное расширение Firefox/Chrome.
Расширение сравнивает выбранные CSV/TSV прямо в браузере, без Python и localhost.
Кристина поясняет результат в диалоге, открывает найденные отличия по вопросу
и готовит редактируемый черновик письма. Ответы ограничены данными текущей сверки.
[Сборка и установка расширения](extension/README.md). Автоматического сбора страниц пока нет.

## Запуск примера

Из корня репозитория, Python 3.11 или новее. Для этой команды достаточно
стандартной библиотеки; ключ LLM и сервер не требуются.

```bash
python3 reconcile_lists.py \
  --left examples/reconciliation/order.csv \
  --right examples/reconciliation/confirmation.csv \
  --key sku \
  --number quantity \
  --field unit \
  --output results/reconciliation.json \
  --html results/reconciliation.html
```

Откройте `results/reconciliation.html` в браузере. Отчёт работает офлайн.
Ожидаемый результат: 4 строки в каждом источнике, 1 совпадение по выбранным
полям, 2 изменённые записи, 1 запись только в A и 1 только в B.

- `CH-100`: `10` и `10.00` равны в явно выбранном числовом режиме.
- `DS-200`: количество изменилось с 5 до 4.
- `LP-300`: единица изменилась с `piece` на `box`; пересчёт не выполняется.
- `OLD-400`: только в заказе; `NEW-500`: только в подтверждении.

Существующие отчёты не перезаписываются. Для повторного запуска задайте новые
имена выходных файлов. Исходники никогда не изменяются.

## Получить уточнения

```bash
python3 reconcile_lists.py \
  --left examples/reconciliation/order.csv \
  --right examples/reconciliation/confirmation.csv \
  --output results/questions.json \
  --html results/questions.html
```

Без ключа и выбранных полей Кристина возвращает `needs_clarification` с
вопросами. Сравнение не выполняется. После выбора правил повторите запуск
с `--key` и `--field` / `--number`. Для сравнения только состава ключей
используйте `--key sku --membership-only`.

Разные названия столбцов задаются парами `левый=правый`:

```bash
python3 reconcile_lists.py \
  --left order.csv --right confirmation.csv \
  --key 'sku=Артикул' --number 'quantity=Количество' --field 'unit=Единица' \
  --output results/comparison.json --html results/comparison.html
```

`--strip` явно разрешает игнорировать пробелы по краям ключей и значений.
Регистр не меняется. Заголовки должны совпадать точно с указанными именами.
Разделитель по умолчанию — запятая; `--delimiter ';'` и `--delimiter tab`
применяются к обоим источникам. CLI-синтаксис не поддерживает `=` внутри имени
столбца; Python API позволяет передать такие имена отдельными строками.

## Что означает завершённая сверка

`complete` подтверждает сравнение всех записей двух предоставленных CSV по
выбранным правилам. Это не подтверждает правильность первичных документов,
полноту выгрузки сайта или эквивалентность товаров. Не выбранные для сравнения
столбцы не влияют на результат.

Каждый результат содержит исходные значения и номера логических CSV-записей,
имена файлов, SHA-256 исходных байтов и точные правила. Заголовок — запись 1;
первая строка данных — запись 2. Переносы внутри ячеек сохраняются, поэтому
номер записи может отличаться от номера физической строки файла.

Пустой ключ, повтор ключа (даже у одинаковых строк), повтор после `--strip`
или неоднозначное число приводят к уточнению без частичных результатов.
Один ключ сопоставляет ровно одну запись с каждой стороны. Составные ключи,
нечёткие совпадения и объединение дублей пока не поддерживаются.

Числа принимаются в виде `-12.50`, `10`, `+5`: ASCII-цифры, точка для дробной
части, без разделителей тысяч и экспонент. Пустота, `NaN`, `Infinity`, `1,5`
не превращаются в ноль. Сравнение через `Decimal` не использует округление
двоичных float. Валюты и единицы измерения не конвертируются; при необходимости
их следует выбрать отдельными текстовыми полями.

CSV: UTF-8, возможен BOM; одинаковое число ячеек в каждой записи, уникальные
непустые заголовки. Лимиты: 2 MiB на источник, 5 000 строк данных, 200 столбцов.
Также действует лимит одной CSV-ячейки стандартного Python-парсера (обычно
131 072 символа); пилот не изменяет глобальную настройку парсера.
Пустой файл отклоняется; CSV только с заголовком представляет пустой список.
Некорректный CSV или конфигурация — `invalid_input`, отчёт не создаётся.

Каждый выходной JSON/HTML ограничен 16 MiB в UTF-8. Лимит проверяется по мере
формирования, до открытия выходных файлов: длинные заголовки и ключи могут
многократно повторяться в отчёте даже при небольшом CSV. При превышении
возвращается `invalid_input`; ни один из запрошенных отчётов не сохраняется.
Разделите списки на меньшие части, сохранив одинаковые группы ключей с обеих сторон.

Коды завершения CLI: `0` — complete (в том числе при найденных различиях),
`2` — needs_clarification, `1` — ошибка входных данных или записи отчёта.
Ошибки аргументов argparse также завершаются кодом `2`, но без JSON-отчёта.

## Подключение к существующей Кристине

Профессия `reconciliation_specialist` зарегистрирована в существующем
`PROFESSION_REGISTRY`. CLI создаёт аватара через `AvatarFactory` и вызывает
его новый метод `reconcile_lists`. Метод проверяет роль и вызывает отдельный
детерминированный исполнитель `avatar_platform.reconciliation`.

```python
from avatar_platform import AvatarFactory

avatar = AvatarFactory().create_avatar(
    user_id="pilot-user", name="Кристина", role_id="reconciliation_specialist"
)
report = avatar.reconcile_lists(
    b"sku,qty\nCH-100,10\n",
    b"article,count\nCH-100,8\n",
    key=("sku", "article"),
    fields=[("qty", "count", "number")],
)
assert report["status"] == "complete"
assert report["summary"]["changed"] == 1
```

Доступность LLM, настроение, энергия и ночной режим не влияют на эту операцию.
CLI внедряет адаптер, запрещающий обращения к модели: нет подмены результата
текстом MockLLM. Данные файла и HTML-отчёт не исполняются как инструкции.
Отчёт экранирует значения ячеек и не загружает внешние ресурсы.

Текущий Telegram-диалог и веб-чат не переключаются автоматически на новую
профессию. Менеджер задач не получает фиктивный статус DONE: пилот возвращает
фактический отчёт напрямую и сохраняет его в файлы. Браузерный сбор,
история рабочих поручений и возобновление после перезапуска — следующие этапы.

## Приёмка пилота

```bash
python3 -m pytest tests/test_reconciliation_engine.py tests/test_reconciliation_cli.py -v
```

Затем сверить реальные обезличенные пары CSV, заранее отметив ожидаемые
расхождения. Для каждой пары измерить время подготовки, время проверки отчёта
и число ручных уточнений. Переходить к сбору из браузера после подтверждения,
что отчёт экономит время с учётом проверки исходных строк.


## Браузерный интерфейс

Отдельный локальный сервер использует тот же профессиональный профиль и
исполнитель, что CLI. Для запуска нужны `fastapi`, `uvicorn` и `anyio`;
для HTTP-тестов также нужен `httpx`. При установке `requirements.txt`
`anyio` устанавливается как зависимость веб-стека. Запуск из корня репозитория:

```bash
python3 reconciliation_web.py
```

Откройте `http://127.0.0.1:8765`. При занятом порте:

```bash
python3 reconciliation_web.py --port 8766
```

### Открыть → загрузить → получить результат

Загрузите два UTF-8 CSV или перетащите их в области A и B. После загрузки
второго файла интерфейс автоматически определяет общий разделитель, предлагает
соответствия столбцов и запускает сверку, если правила однозначны. Кнопка
«Попробовать на примере» проходит этот же путь на встроенной паре CSV.

Автоматическая настройка использует полный разбор обоих файлов и небольшой
явный словарь названий, без LLM и нечёткого поиска:

- Разделитель — запятая, точка с запятой или табуляция. Если несколько
  интерпретаций допустимы, требуется ручной выбор общего разделителя.
- Для ключа нужен один распознанный идентификатор с непустыми уникальными
  значениями. `sku` / `артикул` и `id` / `идентификатор` относятся к разным
  семействам: совпадение значений не делает их взаимозаменяемыми. Количество,
  цена и наименование автоматически ключами не становятся.
- Одноимённые столбцы сопоставляются точно; известные синонимы — только при
  однозначной паре. Количество и распознанная цена проверяются как числа,
  остальные поля — как текст. `цена_руб` не связывается автоматически с
  `price`: указание валюты только с одной стороны требует уточнения.
- Повторяющиеся или пустые ключи, несколько возможных идентификаторов,
  несопоставленные столбцы и неправильный числовой формат останавливают
  автоматический запуск и вызывают вопрос. Значения проверяются во всех
  записях, а не только в первых пяти строках предпросмотра.

Если в двух непустых списках не найдено общих ключей, сначала предлагается
проверить идентификаторы. Если списки действительно не пересекаются, можно
выбрать ключи вручную и продолжить; результат покажет отдельные позиции
каждой стороны и предупреждение об отсутствии пар. Это не считается
совпадением документов.

«Настройки сравнения» позволяют изменить разделитель, ключи, соответствия
полей, числовой/текстовый режим и обработку пробелов. Непроверяемые столбцы
перечислены явно. Чтобы исключить их, подтвердите настройки кнопкой
«Применить настройки» или «Продолжить». Для проверки только состава включите
«Проверить только наличие позиций». Изменение настроек или замена файла
сбрасывает прежний результат. Уточнение от движка означает, что сравнение
не выполнено и частичных итогов нет.

### Содержимое документов и подсветка

Результат показывает две панели A/B с парами записей, выровненными по ключу.
Это представление содержимого CSV, а не воспроизведение исходной вёрстки
документа. Изменённые текстовые фрагменты выделяются внутри значений;
изменённые числа выделяются целиком. Цвет дополнен подписями: «изменено»,
«Только в A», «Только в B». У отсутствующей пары показан пустой блок.

Исходные значения сохраняются, включая пробелы, переносы и исходную запись
ключа при включённом игнорировании пробелов. Подпись пустого значения находится
вне его содержимого. Поля, исключённые из проверки, остаются видимыми с
пометкой «не проверялось»; числовое равенство `10` и `10.00` не подменяет
оригинальные значения. Номера относятся к логическим записям исходного CSV.

Есть фильтры категорий, поиск по ключу, переход к следующему/предыдущему
отличию и страницы по 25 позиций. «Как выполнена сверка» раскрывает источники,
хеши и точные правила. «Скачать отчёт» сохраняет автономный HTML с двумя
панелями, подсветкой, исходными полями и сведениями о проверке; совпавшие
записи доступны в раскрываемом блоке. HTML работает офлайн без JavaScript
и внешних ресурсов. JSON сохраняет полный машинно-читаемый отчёт.

Сейчас поддерживается только CSV, включая файлы с табуляцией как разделителем.
Загрузка PDF, DOCX и обычного TXT, сравнение произвольных текстовых документов,
сохранение их исходной вёрстки и вычитка договоров, докладов или книг пока
не реализованы. Устанавливаемого браузерного расширения также пока нет.

Сервер слушает **только 127.0.0.1**, без удалённого доступа, аккаунтов и
постоянного хранения. Файлы обрабатываются в памяти запроса; сервер не пишет
источники и отчёты на диск. Скачивание сохраняет результат средствами браузера.
Сверка не обращается к модели: используется `NoModelAdapter`. Запуск интерфейса
не импортирует Telegram-бота и не меняет его состояние или профессию.

Это отдельное приложение без аутентификации. **Не подключайте его к
производственному веб-чату и не публикуйте через прокси/туннель.** Удалённый
доступ и многопользовательский режим требуют отдельной реализации. POST
проверяет локальный Host, точное совпадение Origin (если есть), Fetch Metadata
и заголовок `X-Kristina-Reconcile: 1`; CORS не включён. Пользовательские данные
имеют `Cache-Control: no-store`, интерфейс не загружает внешние скрипты.

Лимиты движка сохранены: 2 MiB на CSV, 5 000 записей, 200 столбцов и по 16 MiB
на JSON и HTML. HTTP-тело ограничено 6 MiB **до** разбора JSON, включая запросы
без Content-Length. Не более двух операций одновременно выполняются в рабочем
пуле; CSV-разбор, сверка, генерация и сериализация ответа не блокируют
асинхронный цикл сервера. При превышении выходного лимита отчёт не возвращается.

### Локальный HTTP API

- `POST /api/prepare`: `{left:{name,data}, right:{name,data}, delimiter:"auto"}`.
  `data` — строгий base64 исходных байтов; `auto` используется по умолчанию.
  Ответ содержит `left`/`right` с метаданными и первыми пятью исходными
  записями `preview`, определённый `delimiter`, предложенные
  `rules:{key,fields,strip}`, флаг `ready`, `question` и списки `unmatched`.
  `ready:false` — вопрос пользователю, а не частичная сверка. Только при
  `ready:true` интерфейс автоматически вызывает `/api/compare` с этими
  правилами и определённым разделителем. Сам `/api/prepare` не сравнивает
  документы. Неоднозначный разбор CSV возвращает HTTP 400 с описанием.
- `POST /api/inspect`: `{left:{name,data}, right:{name,data}, delimiter}`.
  `data` — строгий base64 исходных байтов. Ответ для каждой стороны содержит
  `name`, `headers`, `row_count`, `sha256` и первые пять записей `preview`
  с номерами логических CSV-записей и исходными значениями.
- `POST /api/compare`: те же источники плюс `key:[столбец_A,столбец_B]`,
  `fields:[[поле_A,поле_B,"text"|"number"]]` и `strip:boolean`.
  `key:null` или `fields:null` запрашивает уточнение; `fields:[]` — явная
  сверка состава. Ответ `{report,html}` содержит отчёт существующего движка
  и самостоятельный HTML. Статус `needs_clarification` — HTTP 200, не ошибка
  транспорта и не частичный результат.
- Для `/api/inspect` и `/api/compare` разделитель — `,`, `;` или символ
  табуляции; по умолчанию `,`. Значение `auto` принимает только `/api/prepare`.
  Запросы требуют `Content-Type: application/json` и
  `X-Kristina-Reconcile: 1`. Ошибки — HTTP 4xx и `{error:"описание"}`.
- Только `/`, `/assets/app.js`, `/assets/style.css` доступны как статические
  файлы; каталоги репозитория не публикуются.

Предпросмотр намеренно использует существующий внутренний парсер `_source`
движка, чтобы CSV одинаково трактовался в CLI, предпросмотре и итоговом отчёте.
Это локальная связь внутри репозитория, а не новый публичный Python API.

Проверка HTTP-границ и полного пути профессиональной сверки:

```bash

```

Проверка интерфейса через DOM и настоящий локальный HTTP-сервер (Node.js 24):

```bash

```

Это интеграционные проверки действий пользователя, а не визуальные снимки
настоящего браузера. При необходимости задайте `PYTHON=/путь/к/python` перед
`npm test`. Эти проверки также выполняются в CI.
